# UI — HUD, items, held items, menu and settings

The rules the interface code keeps. How each screen looks and behaves for the player is in `docs/GAME.md`; layout conventions shared with `style.css` and `index.html` are in `.claude/rules/layout.md`.

- **The HUD is DOM**, over the canvas: markup in `index.html`, styles in `style.css`, behaviour in `hud.js`. The HUD layer ignores the pointer so drags reach the canvas and the pads; only actual controls take clicks.
- **Prompting** goes through `hud.attention(btn, on)` (glows and keeps its name shown until used: a newly found item that couldn't be held up at once) `hud.fresh(btn)` (a short glow and name when a tool first appears) and `hud.introduce(btn)` (an item that opened by itself when found: its name and a glow the first time it's put away). Toasts go through `hud.toast`; a new toast must be added to GAME.md's Toasts list.
- **Items** (things you hold up to read): a new kind of item needs an entry in `ITEMS` (`main.js`: `has()`, `isOpen()`, `open()`), a button with class `tool item` inside `#items` in `index.html` (its name as `data-i18n-aria` / `data-i18n-title`: the HUD reads the name from its aria-label), and an entry in `hud.itemBtns`. The world decides whether you have it, through its hooks. Items never take each other's place.
- **Held items** share `held.js`: each has `open` and a `hold = { pauses }`, and builds its close button with `heldControls()`. While one is open the game's own input is off (`syncHolding()` → `body.holding` and `input.setHold`); an item's own gestures (the map's zoom, pan and heading dial) are handled on its own elements, which are the only parts of it that take the pointer. Keys stay tracked in `input.keys`, so `main.js` can read an item's shortcuts (the map's A / D) and apply what moves the game (turning the explorer and camera, towards `mapView.aim()` too).
- **Text**: no literal words here or in the markup; see `src/i18n/CLAUDE.md`.
- **Contextual actions** are `{ id, label, icon }` from the world's `action()` hook (the label already translated); their icons live in the `ICONS` table in `hud.js`.
- **Drawn pages** (loading, menu, Settings) use the `.paper` screen look and the shared page tokens in `style.css` (see `.claude/rules/layout.md`, Drawn look). They are opaque, so the game renders nothing while the menu state is on. The pause and end cards are `.card.paper` over the dimmed world. Controls inside any `.paper` element (buttons, switches, setting rows, segmented pickers) take the inked look from shared `.paper …` rules, so a new paper surface gets them for free.
- **The menu illustration** is an SVG string built by `menuArt.js` from `WORLDS` (each world's `theme` and `gem` look), inserted once at startup; it draws nothing world-specific by id. Its motion is CSS classes (`.bob`, `.swirl`, `.drift`, `.glint`, `.twinkle`), so reduced motion stills it in one rule. Ink strokes use `vector-effect: non-scaling-stroke` so far, smaller portals keep the same line weight, as in a drawing.
- **The path not yet drawn** (after the last open world, `GAME.openWorlds`) draws in the same hand: `beyondArt.js` reuses `menuArt.js`'s island portal and ink helpers, so the two drawings never drift apart. Its backdrop is built from the theme of the portal you stepped into.
- **Settings**: general ones in `settings.js`, per-world ones in the world module's `settings` list; each names its text by key (`text` → `.label`, optional `.hint`); debug switches (`GENERAL_DEBUG`, `levelDebugSettings` in `settings.js`, read through `DEBUG`) open each tab in its Debug section, are remembered under their own keys and left alone by Reset to defaults.
