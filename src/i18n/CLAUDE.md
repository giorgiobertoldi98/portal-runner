# i18n — every word the player reads

How text reaches the screen, so adding a language never touches game code. The Language setting, as the player sees it, is in `docs/GAME.md` (Settings).

- **No literal player-facing text in code.** Everything the player reads or hears announced (labels, toasts, hints, aria-labels, titles, text drawn on canvases or textures) goes through `tr(key, vars)`; static markup in `index.html` carries `data-i18n` (text), `data-i18n-html` (text with markup from our own catalogue), `data-i18n-aria` or `data-i18n-title`, filled once by `applyDom()` at startup. The function is `tr`, not `t`: `t` is the time parameter all over the codebase and would shadow it.
- **Where text lives**: the game's own text in one catalogue per language (`en.js`, ...), registered in `LANGUAGES` (`i18n.js`). A world's text lives in its module (`strings: { en: {...}, <lang>: {...} }`), registered by `registry.js` under the world's id and read as `tr('<worldId>.<key>')` (`worldText(def, key)` for the contract keys: `name`, `tab`, `tagline`, `hunter`). Its mechanics use the same namespace. A world id must not match a top-level key of the game catalogue.
- **English is complete; others may be partial**: a key missing in a language falls back to English, and a key missing everywhere logs `[i18n] missing: <key>` and shows the key.
- **Whole sentences, not fragments**: never build a sentence by concatenating translated pieces or by English rules (adding an "s", capitalising a word). Put the whole sentence in the catalogue with `{vars}`; plurals are `{ one, other, ... }` objects (Intl.PluralRules categories) selected by `vars.count`. A list of independent parts (the catch toast) may be joined with ` · `.
- **Names used inside sentences** (a hunter, a world) are written to read well at the start of a sentence ("The Yeti"); translators phrase the templates around them (articles and gender agreement vary by language).
- **Numbers** go through `num(n, digits)` (or as numeric `vars`, formatted the same way), so decimal separators follow the language; units are templates (`units.*`), since spacing and order vary.
- **Text drawn on canvases** (the portal's name, the map) is baked when a world is built. That's why changing language reloads the page (`setLanguage`); don't cache text anywhere that outlives a page load.
- **Room for longer text**: other languages run up to ~35% longer. Layouts must wrap or shrink rather than clip (the portal's label already shrinks to fit). Check a text change with `?lang=pseudo` (every string accented, bracketed and padded): any unbracketed text is hard-coded, and anything clipped needs room.
- **Adding a language**: copy `en.js` to `<code>.js` and translate it, add it to `LANGUAGES` with its own name for itself, and add a `<code>` block to each world's `strings`. The Settings row appears by itself once there are two languages. Fonts: Cinzel (titles) covers Latin scripts only, Caveat (handwriting) Latin and Cyrillic; another script needs a font that covers it. Right-to-left languages would need layout work beyond this.
